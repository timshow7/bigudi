# Бигуди — прототип

**Бигуди — закрутим твою взрослую жизнь.**

Название про подготовку: накрутил на ночь — утром красиво. Сервис помогает
подросткам и студентам подготовиться ко взрослой жизни — бытовые советы, рецепты,
базовая медицина и форум. Навигация построена вокруг плана квартиры:
комната — категория, предмет в комнате — подкатегория.

Учебный проект, один разработчик, без бюджета.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
```

Стек: React 18 + TypeScript + Vite + Tailwind CSS 3 + react-router-dom + lucide-react.
Никаких UI-китов, состояние — обычный `useState`.

## Схема квартиры: почему план сверху, а не изометрия

Рассматривались два варианта.

**Вариант А — SVG-изометрия.** Комнаты рисуются под углом 45°, у каждой пол и
две стены, предметы стоят «в объёме». Выглядит эффектнее.
Минусы: каждая комната — это 3–5 полигонов, координаты которых нужно считать
вручную; порядок отрисовки задаёт, что чем перекрывается, поэтому добавление
шестой комнаты ломает композицию; подписи приходится вписывать в наклонные
плоскости; на мобильном всё это нечитаемо.

**Вариант Б — план сверху (реализован).** Комната — прямоугольник с координатами
`{x, y, w, h}` в `src/data/rooms.ts`. Предметы расставляются внутри в процентах
от комнаты. Добавить комнату = дописать объект в массив, ничего не пересчитывая.
Подписи горизонтальные, ховер и фокус — обычным CSS.

Выбран Б: при разнице во внешнем эффекте процентов в двадцать он в несколько раз
дешевле в поддержке, а для учебного проекта поддерживаемость важнее.
3D-вариант из обсуждения не выброшен — он остаётся как «версия 2.0»,
и текущая структура данных ему не мешает: координаты всё равно лежат отдельно
от отрисовки.

Если захочется добавить объёма малой кровью: `transform: perspective(1200px) rotateX(18deg)`
на `<svg>` даст эффект наклонённого плана, сохранив всю интерактивность.
Проверьте только зоны нажатия — они наклонятся вместе с картинкой.

## Доступность: одно отступление от палитры

В ТЗ акцент действия — `#E07856`. Белый текст на этом цвете даёт контраст
**3.0 : 1**, а WCAG AA требует 4.5 : 1 для обычного текста. Поэтому:

- `accent` (`#E07856`) — иконки, подчёркивания вкладок, подложки, кольцо фокуса, рамки;
- `accent-strong` (`#B4552F`) — фон залитых кнопок и цветной текст (**5.3 : 1**).

Визуально это та же терракота, просто темнее на полтона. Аналогично добавлен
`muted-strong` (`#6B6359`): исходный `#7A7268` проходит AA на белых карточках
(4.74), но на кремовом фоне страницы даёт 4.40 — чуть ниже нормы.

Зелёный `#4A7C59` закреплён **только за форумом**, поэтому комнатам он не
достаётся: иначе пользователь перестаёт считывать зелёный как «обсуждения».

## Структура

```
src/
├── data/            # весь контент: комнаты, статьи, темы форума
├── types.ts         # типы данных
├── lib/             # cn(), склонения, таблица акцентных классов
├── hooks/           # имитация загрузки, медиазапрос
├── store/           # общее состояние: избранное, свои темы и ответы, профиль
├── components/
│   ├── ui/          # переиспользуемые примитивы (кнопка, чипс, табы, аватар…)
│   ├── layout/      # шапка, подвал, прокрутка наверх
│   ├── cards/       # карточки комнаты, предмета, статьи, темы
│   ├── blocks/      # совет дня, телеграм-бот, фильтры, «спросить на форуме»
│   ├── article/     # тело статьи из блоков, оглавление, лайк и сохранение
│   ├── forum/       # ответ в треде и форма ответа
│   └── apartment/   # план квартиры и сцена комнаты
└── pages/           # экраны, соответствуют маршрутам
```

Данные отделены от отрисовки намеренно: когда появится backend, меняются только
функции в `src/data/*`, компоненты остаются как есть.

## Если у вас Tailwind 4

Проект собран на Tailwind 3 (конфиг в `tailwind.config.js`). Для четвёртой версии
конфиг не нужен — те же токены объявляются прямо в CSS:

```css
@import 'tailwindcss';

@theme {
  --color-paper: #faf6f0;
  --color-ink: #2e2a26;
  --color-accent: #e07856;
  --color-accent-strong: #b4552f;
  /* …остальные цвета так же */
}
```

Имена классов (`bg-paper`, `text-accent-strong`) при этом не меняются.

## Общее состояние

`src/store/AppState.tsx` — React Context поверх `useState`. Там живёт то, что
нужно нескольким экранам сразу: сохранённые статьи, созданные темы, свои ответы
и настройки профиля. Состояние пишется в `localStorage` одной записью
(`bigudi:state:v1`), поэтому созданная тема переживает перезагрузку страницы.

Redux здесь не нужен: данных мало, обновления редкие. Когда появится backend,
этот файл станет тонкой обёрткой над запросами, а экраны не изменятся.

## Как устроен текст статьи

Статья хранится не строкой HTML, а массивом блоков (`src/data/articleBodies.ts`):
`paragraph`, `heading`, `list`, `steps`, `callout`. Вёрстка каждого блока живёт
в `ArticleBody.tsx`.

Так сделано по двум причинам. Первая — безопасность: статьи будут писать
пользователи, и вставлять их разметку через `dangerouslySetInnerHTML` нельзя.
Вторая — оглавление: заголовки уже размечены как данные, и собрать из них
навигацию по статье можно без разбора HTML.

## Как продолжить разработку без меня

План на пять шагов — в том порядке, в котором их стоит делать.

**Шаг 1. Наполнить контент (1–2 вечера, кода не требует).**
Открыть `src/data/articles.ts` и `src/data/articleBodies.ts` и дописать статьи
по образцу раздела «Стиральная машина». Формат блоков: `paragraph`, `heading`,
`list`, `steps`, `callout`. Это самая дешёвая работа с самым заметным эффектом:
прототип перестаёт выглядеть демонстрационным.

**Шаг 2. Поднять backend и заменить чтение данных.**
Подойдёт FastAPI или Express + SQLite. Таблицы повторяют `src/types.ts`:
`rooms`, `items`, `articles`, `article_blocks`, `topics`, `replies`, `users`.
В коде меняется ровно одно место — хук `useSimulatedLoad`: вместо `setTimeout`
там будет `fetch`. Сигнатура (`status`, `data`, `retry`) остаётся, поэтому
экраны с их загрузкой, ошибками и кнопкой «Повторить» не трогаются.

**Шаг 3. Авторизация.**
Проще всего через Telegram Login Widget: он бесплатный, не требует паролей
и уже вписан в продукт. После входа `store/AppState` перестаёт быть
единственным источником правды — избранное, темы и ответы уезжают на сервер,
а в состоянии остаётся кэш. Профиль и лайки к этому уже готовы: они работают
через `articleId` и `topicId`, а не через локальные индексы.

**Шаг 4. Телеграм-бот.**
Библиотека `aiogram`, тот же backend. Минимум: `/start` с привязкой аккаунта,
уведомление о новом ответе на свою тему, команда «сохранить статью».
Кнопка «Привязать Telegram» в профиле уже стоит на своём месте — ей нужен
только настоящий обработчик.

**Шаг 5. Модерация и жалобы.**
Кнопка «Пожаловаться» у темы и ответа, скрытие по жалобам, простая админка
на отдельном маршруте. Это то, без чего форум нельзя открывать посторонним.

Чего делать не стоит, пока не пройдены шаги 1–3: нативное приложение,
сложную систему достижений и рекомендации «умным алгоритмом». Они дорогие,
а на защите проекта добавляют меньше, чем живой контент и работающий вход.
